# 技术笔记

## 检查规则和资产要求分开

`mesh_checks.py` 读取网格和材质，返回问题列表；`core.py` 中的 `Policy` 保存预算和允许条件。面数统计是事实，是否超预算则由配置决定。

边界和 0–1 以外的 UV 默认允许，因为薄片和平铺材质都可能需要它们。纯色材质没有图片采样需求时，也不要求 UV。缺图、缺 UV 和材质节点使用情况需要一起判断。

拓扑检查使用临时 BMesh，查询完释放，不写回源网格。当前读取基础 Mesh，不计算修改器最终结果。

## 为什么复制 Object 和 Mesh

Blender 的 Object 保存名称和变换，Mesh 保存顶点、边和面。只复制 Object 可能仍然共享 Mesh，所以交付时两者都复制。材质和图片只读使用。

副本放入临时场景，静态父子关系转换为世界变换。修改器、动画、约束等未经验证的情况直接阻止交付。原件名称不变，名称映射写入报告。

交付结束后清理临时数据，恢复原场景、选区和活动对象。测试不仅检查成功输出，也检查导出异常和复验失败之后的场景状态。

## 导出成功不等于文件正确

`delivery.py` 先导出 `candidate.glb`，再重新导入。副本携带验证 ID，用来对应导出前后的对象。比较项为对象 ID、三角面数、世界空间包围盒和已使用材质槽数量；同时检查 GLB 内嵌缓冲与图片引用范围。

不直接比较顶点数。glTF 导出可能在 UV 接缝或硬法线处拆分顶点，顶点数量变化不一定表示表面发生变化。

通过后才生成 `asset.glb`。如果导出失败或比较不一致，报告记为 FAILED，候选文件只用于诊断。材质参数、像素与渲染效果尚未比较，这是当前复验的边界。

## 高斯 PLY 单独处理

PLY 后缀不能确定数据类型。高斯参数没有网格的面、UV 和 PBR 材质，不能套用相同规则。

当前解析器只支持 vertex-only、little-endian、float32 的 Graphdeco-like 数据，检查字段、长度和数值。低点数表示需要复核，不直接判定文件损坏。原始 opacity 和 scale 可能是激活前或对数参数，负值本身不算错误；具体含义仍取决于生成数据的程序。
